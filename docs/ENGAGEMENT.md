# 作品互动指标

焚诀在作品详情页记录四类真实互动：浏览、复制、喜欢与快捷表情 Reaction。首页继续保持图片优先，不在瀑布流卡片堆叠数字；管理总览只显示全站汇总。

实测心得不属于互动计数：它是有正文、可选平台和审核状态的用户内容，存放在独立评价模型中。编辑精选和专栏也不参与喜欢或表情回应聚合，避免平台判断与用户反馈互相污染；详见 [`EDITORIAL.md`](EDITORIAL.md)。

## 统计口径

| 指标 | 是否登录 | 计数规则 |
|---|---|---|
| 浏览 | 否 | 同一匿名访客、同一作品、同一 UTC 日期最多计 1 次 |
| 复制 | 否 | 浏览器成功写入剪贴板后上报；同一匿名访客、同一作品、同一 UTC 日期最多计 1 次 |
| 喜欢 | 是 | 每位用户对每条作品只有一个喜欢状态，再点一次取消 |
| 表情回应 | 是 | 每位用户对每条作品最多选择一个；切换会移动反馈，再点当前回应取消 |

四个表情围绕 AI 生图浏览与复用场景设计，不代表提示词复杂度、技术门槛或编辑评级：

- 🔥 灵感燃了：画面点燃灵感，值得马上收藏复用。
- 🪄 神来一笔：成片有意外惊喜，视觉表达很出彩。
- 🧪 想炼同款：提示词勾起尝试欲，想复制后亲自生成。
- 💡 学到一招：提示词或技巧提供了可复用的新思路。

详情页用一个表情入口展开完整选项；已有票数的回应以胶囊常驻，既能快速查看分布，也能直接选择或取消。存储层暂时保留既有 `tian / di / xuan / huang` 标识以延续已产生的真实票数，前台不再把这些标识解释为等级。

浏览和复制数字是“去重日次数”，不是全周期独立人数。同一访客第二天再次访问同一作品会产生新的有效记录。

## 数据模型

- `prompt_engagement_totals`：每条作品一行的累计汇总，详情页和管理总览直接读取。
- `prompt_metric_events`：最近 180 天浏览与复制的每日幂等键，用于去重和近期审计，不向客户端开放明细。
- `prompt_metric_daily_totals`：永久保留的作品每日浏览与复制汇总，原始事件归档后仍然存在。
- `prompt_metric_archive_batches`：私有 R2 压缩归档的可重试清单、校验摘要和完成状态。
- `prompt_likes`：登录用户与作品的喜欢关系。
- `prompt_reactions`：登录用户与作品的单一表情回应关系。

数据库触发器在事件、喜欢或回应关系变化时原子更新汇总。应用只调用以下 RPC，不直接写底层表：

- `record_prompt_event()`
- `get_prompt_engagement()`
- `toggle_prompt_like()`
- `toggle_prompt_reaction()`
- `admin_get_engagement_overview()`

所有互动只接受已经审核通过并公开的作品。作品被退回、驳回或下架后不再接受公开互动，但已有累计数字不会被自动清零。

## 匿名与安全边界

- 浏览器使用随机、不透明的 `fj_visitor` HttpOnly Cookie；它不是登录或授权凭据。
- 服务端只向数据库写入 Cookie 原值的 SHA-256 摘要，不保存原始访客 ID、IP、User-Agent 或邮箱。
- 喜欢与 Reaction 必须通过 Supabase Auth 会话，并要求同源请求；匿名用户只能浏览和复制。
- RLS 在四张互动表上全部启用，直接写权限被撤销；RPC 固定空 `search_path` 并在数据库内再次检查公开状态、登录身份或管理员角色。
- 唯一约束和事务级锁保证重复上报、快速连点或并发请求不会让汇总数字重复增长。

Supabase Advisor 会把暴露给 `anon` 或 `authenticated` 的 `SECURITY DEFINER` RPC 标为 Warning。这里是有意保留的受控例外：RPC 需要在不开放底层表写权限的前提下完成原子聚合；每个函数都固定空 `search_path`、不执行动态 SQL、只授予最低所需角色并在内部重新校验公开状态或身份，私有触发器和 payload 函数不允许客户端执行。

## 产品与运维边界

- Vercel Web Analytics 继续用于站点级访问与渠道观察；Speed Insights 用于真实用户性能；它们不替代作品级业务指标。
- 当前管理后台只有全站累计汇总，不提供趋势、来源拆分、作品排行、用户明细或导出。
- 每日去重能降低刷新和连续点击造成的噪声，但不是完整的反作弊系统；代理切换、清除 Cookie 或自动化流量仍可能产生偏差。
- 浏览与复制的原始事件默认在 Supabase 在线保留 180 天；更早事件按批次压缩为 NDJSON + Gzip，校验后转存到独立的私有 R2 桶。累计值和每日汇总不因归档而减少。
- 喜欢、Reaction 和用户实测心得是当前状态或正式内容，不属于可归档流水，继续保留在 Supabase。
- 归档任务失败时不会删除原事件；批次会释放租约并在后续定时任务中覆盖同一对象后重试。完整运维说明见 [`ANALYTICS_RETENTION.md`](ANALYTICS_RETENTION.md)。
