# 管理后台

焚诀的管理后台位于 `/admin`。它只向 `profiles.role = 'admin'` 的账户开放，用于维护全站内容、用户角色和受控分类；上传仍统一使用 `/submit`，不区分管理员上传和普通用户上传。超级管理员也是管理员，但额外拥有数据库唯一的 `is_super_admin` 标记。

## 信息架构

- `/admin`：关键数量、最近内容和常用入口。
- `/admin/content`：按待审核、已通过、已驳回和关键词搜索全站作品，进入单条审核、编辑或永久删除。
- `/admin/content/[id]/edit`：编辑指定作品的文字、来源、内容关系、分类、标签、验证平台、NSFW 和图片，并独立给出审核结论。
- `/admin/users`：查看注册、邮箱验证、最近登录和角色；唯一超级管理员可以授予或撤销普通管理员权限。
- `/admin/taxonomy`：创建和编辑主分类、风格、形式、主题标签，控制排序和启停状态。

用户管理当前聚焦身份与授权，不包含封禁、删除账户和用户资料代改；后台也暂不包含举报、批量操作或完整业务统计。

## 权限边界

页面加载和每个 Server Action 都会通过 Supabase Auth 重新读取当前用户，并检查 `profiles.role`。界面是否显示按钮不作为安全边界；数据库仍使用 RLS 限制未发布内容和管理操作。

- 未登录用户访问 `/admin` 会被送往登录页。
- 普通用户访问 `/admin` 会回到账户页，并看到权限不足提示。
- 管理员可以读取、更新和删除全部作品，也可以维护分类和标签。
- 普通管理员可以查看用户，但只有唯一超级管理员可以调整其他账户的角色。
- 超级管理员标记和超级管理员自身角色都不能通过后台修改，系统始终最多只有一个超级管理员。
- `profiles.role` 与 `is_super_admin` 不能由普通用户自行修改，初始化和授权方式见 [`AUTH.md`](AUTH.md)。

内容编辑由数据库函数在一个事务中更新作品、图片顺序、标签和已验证平台，但不会隐式改变审核结论。服务器会校验图片只能来自该作品已有对象或当前管理员刚上传的 R2 对象，数据库再校验所有 object key 必须位于 `prompts/` 安全目录内。

## 审核与公开

作品状态分为 `pending`、`approved`、`rejected`。新投稿默认待审核；只有管理员选择“通过并公开”后，数据库才会同时写入 `review_status = 'approved'`、`published = true` 和发布时间。驳回必须填写原因，投稿者可以在账户页看到当前状态和驳回原因；退回待审核或驳回都会立即从公开作品流、详情与 Sitemap 移除。

每次审核决策都会写入 `prompt_reviews`，保留审核人、结论、备注与时间。普通用户无法直接修改审核字段；如果普通用户以后修改自己的内容，数据库触发器会强制重新进入待审核。审核操作完成后通过 `updateTag("prompts")` 主动刷新公开作品缓存。

## 单张图片编辑

编辑器可以修改每张图片的替代文本和顺序，也可以只移除其中一张。移除操作先在浏览器内标记并提供撤销，不会立即改变数据库或 R2；管理员点击“保存修改”且数据库事务成功后，服务器才清理被移除的 R2 对象。每条作品始终至少保留一张、最多八张图片。

Supabase 与 R2 不能加入同一事务。若内容已经保存但旧图片清理失败，后台会显示警告；作品仍然可用，只会留下需要人工清理的孤儿对象。

## 分类与标签

词表 key 创建后保持不变，后台只编辑名称、排序和启停状态，避免公开筛选 URL 漂移。仍被公开作品使用的分类或标签不能停用，需要先逐条调整相关作品。

## 永久删除整条作品

永久删除需要完整配置以下 R2 服务端变量：

```dotenv
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
```

未配置时整条删除和单张图片移除都不可用，管理员仍可编辑内容或退回待审核。执行整条删除时先删除 Supabase 记录，再清理对应的 R2 对象，避免先删图片后数据库失败导致公开作品破图。如果数据库删除成功但 R2 清理失败，后台会明确提示需要人工检查存储对象。
