# 内容管理

焚诀的管理后台位于 `/admin`。它只向 `profiles.role = 'admin'` 的账户开放，用于维护全站文生图作品；上传仍统一使用 `/submit`，不区分管理员上传和普通用户上传。

## 当前能力

- 按全部、展示中、已下架筛选作品。
- 按标题、作者名称或作品编号搜索。
- 查看图片封面、图片数量、作者、创建时间和公开详情。
- 将公开作品下架，或将已下架作品恢复展示。
- 永久删除作品数据库记录和对应的 R2 图片。
- 每页展示 20 条作品，数据查询和计数均由 Supabase 完成。

第一版不包含用户管理、审核队列、举报、批量操作和数据统计。这些能力需要独立确认产品规则后再增加。

## 权限边界

页面加载和每个 Server Action 都会通过 Supabase Auth 重新读取当前用户，并检查 `profiles.role`。界面是否显示按钮不作为安全边界；数据库仍使用 RLS 限制未发布内容和管理操作。

- 未登录用户访问 `/admin` 会被送往登录页。
- 普通用户访问 `/admin` 会回到账户页，并看到权限不足提示。
- 管理员可以读取、更新和删除全部作品。
- `profiles.role` 不能由普通用户自行修改，管理员授权方式见 [`AUTH.md`](AUTH.md)。

## 上下架与缓存

下架会将 `prompts.published` 改为 `false` 并清空 `published_at`；恢复展示会重新写入发布时间。操作完成后通过 `updateTag("prompts")` 主动刷新公开作品缓存。

## 永久删除

永久删除需要完整配置以下 R2 服务端变量：

```dotenv
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
```

未配置时删除按钮不可用，管理员仍可先将作品下架。执行删除时先删除 Supabase 记录，再清理对应的 R2 对象，避免先删图片后数据库失败导致公开作品破图。两个服务无法组成同一事务；如果数据库删除成功但 R2 清理失败，后台会明确提示需要人工检查存储对象。
