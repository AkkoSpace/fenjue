# 管理后台

焚诀的管理后台位于 `/admin`。它只向 `profiles.role = 'admin'` 的账户开放，用于维护全站内容、编辑推荐、用户心得、用户角色、受控分类和生成模型目录；上传仍统一使用 `/submit`，不区分管理员上传和普通用户上传。超级管理员也是管理员，但额外拥有数据库唯一的 `is_super_admin` 标记。

## 信息架构

- `/admin`：关键数量、待审心得、专栏数量、全站浏览/复制/喜欢/作品回应汇总、统计明细在线量与归档状态、最近内容和常用入口。
- `/admin/content`：按审核状态、导入资料状态、主分类和关键词组合筛选全站作品，进入单条审核、编辑或永久删除。
- `/admin/content/[id]/edit`：编辑指定作品的文字、来源、内容关系、分类、标签、验证平台、NSFW、精选推荐、专栏归属和图片，并在同一筛选队列内连续审核。
- `/admin/comments`：按状态查看用户实测心得，填写审核备注并逐条通过或驳回。
- `/admin/collections`：创建专栏草稿、维护标题和简介、控制公开状态与全站排序；作品和专栏的关系在单条内容编辑页维护。
- `/admin/users`：查看注册、邮箱验证、最近登录和角色；唯一超级管理员可以授予或撤销普通管理员权限。
- `/admin/taxonomy`：创建和编辑主分类、风格、形式、主题标签，控制排序和启停状态。
- `/admin/models`：创建和编辑可选择的生成模型，维护名称、说明、Logo、官网、排序和启停状态，并查看作品与心得引用数。

用户管理当前聚焦身份与授权，不包含封禁、删除账户和用户资料代改；后台也暂不包含举报、批量操作、互动趋势图、单条排行、评价回复或数据导出。

## 精选、专栏与评价

「司录精选」是编辑推荐：管理员在单条内容编辑器中开关精选，填写 2-160 字推荐语和排序。精选只在作品已经通过审核并公开时出现在首页，不能替代用户喜欢或表情回应。

「专栏」是有顺序的主题目录：先在专栏管理创建草稿，再从单条作品编辑器将作品加入一个或多个专栏并设置各自位置，内容准备好后才对外发布。公开 URL 使用创建后不再修改的英文标识，已发布专栏自动进入 Sitemap。

「实测心得」由登录用户在公开作品下提交，长度 10-500 字，可选择实际使用的平台。所有心得默认 `pending`；管理员通过后才向访客公开，驳回必须填写原因，作者可以在作品页和账户页看到自己的待审或驳回记录并删除自己的记录。完整边界见 [`EDITORIAL.md`](EDITORIAL.md)。

## 互动指标

管理总览汇总全部作品的浏览、复制、喜欢和表情回应。浏览与复制按同一匿名访客、同一作品、同一 UTC 日期去重；喜欢是登录用户对作品的独立二元选择；表情回应是登录用户对作品的单选反馈。汇总数字用于观察内容使用情况，不等同于独立自然人数，也不替代 Vercel Web Analytics 的站点访问与性能指标。详细边界见 [`ENGAGEMENT.md`](ENGAGEMENT.md)。

管理总览同时展示 Supabase 在线明细数量、已经归档的事件与压缩体积。归档未配置或有批次等待重试时会明确显示，但不会为了消除告警而删除原始数据。历史归档使用独立私有 R2 桶，配置和恢复方式见 [`ANALYTICS_RETENTION.md`](ANALYTICS_RETENTION.md)。

## 权限边界

页面加载和每个 Server Action 都会通过 Supabase Auth 重新读取当前用户，并检查 `profiles.role`。界面是否显示按钮不作为安全边界；数据库仍使用 RLS 限制未发布内容和管理操作。

- 未登录用户访问 `/admin` 会被送往登录页。
- 普通用户访问 `/admin` 会回到账户页，并看到权限不足提示。
- 管理员可以读取、更新和删除全部作品，也可以维护分类、标签和生成模型目录。
- 管理员可以设置精选、维护专栏并审核实测心得；普通用户不能直接写入这些编辑和审核字段。
- 普通管理员可以查看用户，但只有唯一超级管理员可以调整其他账户的角色。
- 超级管理员标记和超级管理员自身角色都不能通过后台修改，系统始终最多只有一个超级管理员。
- `profiles.role` 与 `is_super_admin` 不能由普通用户自行修改，初始化和授权方式见 [`AUTH.md`](AUTH.md)。

内容编辑由数据库函数在一个事务中更新作品、图片顺序、标签和已验证平台，但不会隐式改变审核结论。精选与专栏归属由第二个受控事务 RPC 原子更新；若前一个内容事务成功而编辑编排失败，后台会明确警告并要求重新打开检查。服务器会校验图片只能来自该作品已有对象或当前管理员刚上传的 R2 对象，数据库再校验所有 object key 必须位于 `prompts/` 安全目录内。

## 审核与公开

作品状态分为 `pending`、`approved`、`rejected`。新投稿默认待审核；只有管理员选择“通过并公开”后，数据库才会同时写入 `review_status = 'approved'`、`published = true` 和发布时间。驳回必须填写原因，投稿者可以在账户页看到当前状态和驳回原因；退回待审核或驳回都会立即从公开作品流、详情与 Sitemap 移除。

每次审核决策都会写入 `prompt_reviews`，保留审核人、结论、备注与时间。普通用户无法直接修改审核字段；如果普通用户以后修改自己的内容，数据库触发器会强制重新进入待审核。审核操作完成后通过 `updateTag("prompts")` 主动刷新公开作品缓存。

内容列表支持组合筛选并把条件保留到单条审核页。审核页提供上一条、下一条和可展开的历史记录；处理待审核作品后，如果队列仍有下一条，会自动进入下一条。该流程只提高逐条审核效率，不包含批量通过或自动审核，管理员仍需对每条内容单独给出结论。

## 单张图片编辑

编辑器可以修改每张图片的替代文本和顺序，也可以只移除其中一张。移除操作先在浏览器内标记并提供撤销，不会立即改变数据库或 R2；管理员点击“保存修改”且数据库事务成功后，服务器才清理被移除的 R2 对象。每条作品始终至少保留一张、最多八张图片。

Supabase 与 R2 不能加入同一事务。若内容已经保存但旧图片清理失败，后台会显示警告；作品仍然可用，只会留下需要人工清理的孤儿对象。

## 分类与标签

词表 key 创建后保持不变，后台只编辑名称、排序和启停状态，避免公开筛选 URL 漂移。仍被公开作品使用的分类或标签不能停用，需要先逐条调整相关作品。

## 生成模型目录

模型目录存放在 Supabase `ai_tools`，投稿、单条内容编辑、作品详情和实测心得都读取同一份数据。管理员可以维护显示名称、160 字以内说明、HTTPS Logo 地址、HTTPS 官网地址、排序和启停状态；英文 key 创建后保持不变，用于作品与心得外键。

停用只影响新的选择：已有作品与心得继续展示该模型的名称和 Logo，管理员编辑旧作品时也可以保留原有关联或主动移除。只有作品引用和心得引用都为 0 的模型可以永久删除，数据库外键同时防止并发情况下误删历史目录项。

## 永久删除整条作品

永久删除需要完整配置以下 R2 服务端变量：

```dotenv
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
```

未配置时整条删除和单张图片移除都不可用，管理员仍可编辑内容或退回待审核。执行整条删除时先删除 Supabase 记录，再清理对应的 R2 对象，避免先删图片后数据库失败导致公开作品破图。如果数据库删除成功但 R2 清理失败，后台会明确提示需要人工检查存储对象。
