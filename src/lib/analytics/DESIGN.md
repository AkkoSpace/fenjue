# 统计归档服务设计

## 设计目标

长期保留作品互动分析能力，同时阻止高频浏览与复制事件无限占用 Supabase 主库；任何跨服务故障都不得先删除唯一一份原始数据。

## 关键决策

- 最近 180 天匿名事件作为热数据留在 Supabase，永久累计和每日汇总始终在线；历史事件使用内置 Gzip 压缩为逐行可恢复的 NDJSON，避免在 Vercel 函数中引入大型列式存储运行时。
- R2 归档桶必须与公开图片桶不同，不绑定公开域名；配置检查会拒绝将 `R2_ANALYTICS_BUCKET_NAME` 指向 `R2_BUCKET_NAME`。
- 定时接口只接受与 `CRON_SECRET` 常量时间比较通过的 Bearer 凭据；Supabase secret key 只存在于 `server-only` 模块，不进入客户端包。
- 数据库先为事件写入批次 ID 和租约，R2 上传后验证对象长度、事件数元数据和压缩体 SHA-256，最后由单个 RPC 同时删除事件、完成清单并更新计数。
- R2 与 Supabase 没有跨服务事务。失败批次保留原事件并释放租约；重试使用相同 object key 覆盖写入，数据库完成步骤保持幂等边界。
- 单批最多 25,000 条且一次 Cron 只处理一批，以约束 Vercel 内存与执行时间；持续积压时通过增大安全批量或提高执行频率扩容。
- 原始事件不含 IP、User-Agent、邮箱或原始访客 Cookie；长期归档只保存现有 SHA-256 访客摘要和事件字段。
- 三张归档表与原始事件表启用 RLS 但故意不配置直接读取策略；客户端角色的表权限也被撤销。管理总览使用固定空 `search_path`、无动态 SQL并在入口调用 `is_admin()` 的 `SECURITY DEFINER` RPC，因此 Supabase Advisor 的“authenticated 可执行 definer 函数”和“RLS 无策略”提示是经过审计的受控例外。

## 威胁模型

- 未授权触发归档：由不可公开的 `CRON_SECRET` 和 401 默认拒绝阻断。
- 特权密钥泄露：服务端模块、无 `NEXT_PUBLIC_` 前缀、独立私有桶令牌和文档化最小权限降低影响面。
- 部分失败导致丢数：先校验 R2，再在数据库事务中删除；失败只标记批次，不删除原行。
- 重复执行导致重复归档或重复计数：批次租约、固定批次 ID、事件数量核对和覆盖式 object key 保证可重试。
- 公开图片域名泄露统计：代码拒绝共用公开图片桶，归档桶不得启用公开访问。

## 已知限制

- 当前文件格式是 NDJSON + Gzip，不具备 Parquet 的列裁剪能力；它更适合现阶段低依赖、可恢复的冷归档。需要直接分析大量历史事件时再异步转换为 Parquet。
- 应用只能验证配置项存在，无法预先判断 R2 令牌是否真的拥有私有桶读写权限；首次任务结果与后台重试状态是最终验证。
- 当前每天处理一个批次，极端增长下需要调整 Cron 频率或迁移到专用队列工作进程。
- 新增归档索引在产生 180 天以上事件与首个批次前会被 Advisor 标记为未使用；它们服务于到期扫描、领取批次和重试读取，不能因初期数据少而移除。

## 变更历史

### 2026-08-24 - 建立统计数据生命周期

新增永久每日汇总、数据库批次租约、私有 R2 压缩归档、Vercel Cron 入口、存储计数和管理总览状态。在不清除现有互动数据的前提下，为高频匿名事件建立可验证、可重试的冷归档路径。
