# 管理后台服务设计

## 设计目标

为管理后台提供可审计的内容、编辑编排、评价审核、用户角色、分类和生成模型目录维护闭环，同时保持公开浏览和统一上传流程不变。

## 方案选择

后台采用 Next.js Server Components 查询数据、Server Actions 执行变更。作品的跨表编辑使用 Supabase 事务 RPC；没有新增管理专用上传入口，编辑器新增图片继续复用现有 R2 预签名上传接口。

## 关键决策

- 页面加载和每个 Action 都重新调用 `requireAdmin()`，界面按钮不作为权限边界。
- 总览只通过 `admin_get_engagement_overview()` 读取全站互动汇总，不暴露匿名事件、用户喜欢或表情回应明细。
- 总览通过 `admin_get_analytics_storage_overview()` 读取常数时间维护的在线/归档计数和批次状态；不读取匿名事件内容，也不持有 Supabase secret key。
- 超级管理员仍使用 `admin` 角色访问后台；只有唯一的 `is_super_admin` 可以调整其他用户角色，超管自身不可降级。
- `admin_list_users()` 与 `admin_set_user_role()` 因需要访问 Auth 邮箱或受保护角色列而使用 `SECURITY DEFINER`；只向 `authenticated` 开放，函数入口分别再次校验管理员和唯一超管，参数化查询且固定空 `search_path`。这是经过审计的受控例外。
- 搜索词、页码、审核状态、导入资料状态、主分类和作品 UUID 在服务端约束后再进入查询。
- 内容列表的组合筛选会传递到单条审核页；相邻项使用 `created_at + id` 稳定排序，避免批量导入时相同时间戳破坏连续导航。
- 单条作品保存由 `admin_update_prompt_content()` 在一个数据库事务中更新作品、图片、标签和验证平台，不修改审核结论。
- 精选和专栏归属由 `admin_set_prompt_editorial()` 在另一个数据库事务中原子替换；编辑推荐和用户表情回应保持独立语义。
- 专栏英文标识创建后保持稳定；发布状态与作品归属分离，隐藏专栏不会删除编排关系。
- 用户心得默认待审核，`admin_review_prompt_comment()` 是唯一审核写入口；驳回必须有原因，每次结论写入独立历史表。
- 内容事务的旧实现移入未暴露给 PostgREST 的 `private` schema；公开包装函数使用 `SECURITY INVOKER` 并再次校验管理员，避免新增可执行的提权函数。
- 新投稿默认 `pending`；`admin_review_prompt()` 是唯一面向应用开放的审核入口，通过时才同步公开，驳回必须填写原因，决策同时写入 `prompt_reviews`。
- 普通用户的新建和修改由数据库触发器强制回到待审核，避免绕过界面直接公开或在审核后静默换内容。
- 删除单图先在客户端暂存，可撤销；数据库保存成功后才清理 R2。至少保留一张图片。
- 新图片只能使用当前管理员上传前缀；已有导入图片允许保留，但数据库统一限制在 `prompts/` 安全目录并拒绝路径穿越。
- 分类和标签的 key 保持不可变；仍有公开内容使用时不能停用。
- 生成模型的 key 保持不可变；停用后不再用于新投稿或新心得，但历史关联继续可读；只有作品和心得引用均为 0 时允许硬删除。
- 审核状态变化后通过 `updateTag("prompts")` 刷新公开内容缓存。
- 待审核作品通过或驳回后自动进入当前筛选队列的下一条；错误始终停留在当前作品，且不提供批量通过入口。
- 单条审核页采用图片优先的审阅台：标题与提示词保持直接可见，分类、来源、模型和编辑编排通过带摘要的原生 `details` 渐进展开；桌面端审核操作条保持可达，移动端回归普通文档流避免遮挡。
- 永久删除要求完整 R2 写入配置，先删除 Supabase 记录，再清理 R2 图片。
- 操作后的返回地址只允许 `/admin` 及其子路径，避免开放重定向。

## 已知限制

- Supabase 与 R2 不支持跨服务事务；数据库删除成功而 R2 清理失败时会留下孤儿对象，并向管理员显示人工检查提示。
- 当前没有批量审核、举报处理、用户封禁/删除、评价回复、互动趋势与排行、数据导出和自动化孤儿对象清理。
- 项目尚未引入单元测试框架，当前通过类型、Lint、生产构建、安全扫描和浏览器检查验证。

## 变更历史

### 2026-08-24 - 增加统计存储状态

管理总览新增在线匿名事件、私有 R2 历史归档数量与体积、最近完成时间和失败重试提示。页面只读取受控管理员 RPC，不暴露访客摘要、归档 object key 或特权凭据。

### 2026-08-24 - 重构图片优先审核工作台

将单条审核页从同时展开的长表单重排为紧凑队列头部、图片优先双栏审阅台和常驻审核操作条；次要元数据保留摘要并按需展开。保存内容与给出审核结论继续分离，数据库事务、审核历史和权限检查均不变。

### 2026-08-24 - 增加生成模型目录管理

新增模型管理页面与受控写入策略；名称、说明、Logo、官网、排序和启停来自 Supabase，所有选择器和展示读取同一目录。已被作品或心得引用的模型只能停用，不能删除。

### 2026-08-22 - 增加精选、专栏与评价审核

单条作品编辑器新增精选推荐和多专栏编排；后台新增专栏维护与用户实测心得审核，公开查询只返回已发布专栏、已公开作品和已通过心得。

### 2026-08-22 - 增加作品互动汇总

管理总览新增浏览、复制、喜欢和表情回应总数；后台只读取聚合结果，不查询匿名事件或用户选择明细。

### 2026-08-22 - 优化连续审核工作台

内容列表新增导入资料状态与主分类组合筛选；单条审核页保留队列上下文，提供上一条、下一条、处理后自动前进和审核历史展开查看，降低大批量待审核内容的重复导航成本。

### 2026-08-21 - 建立投稿审核闭环

新投稿与普通用户修改默认进入待审核；管理员在单条页面通过、驳回或退回待审核，公开状态由审核结论派生，并保留逐次审核记录。

### 2026-08-21 - 扩展为模块化管理后台

新增总览、用户管理、分类管理和指定作品编辑；支持单张图片排序、替代文本、暂存移除与保存后清理，同时将角色调整限制为唯一超级管理员。

### 2026-08-06 - 建立第一版内容管理模块

新增作品搜索、状态筛选、分页、上下架与永久删除，并将管理员角色校验集中到服务端授权模块。
